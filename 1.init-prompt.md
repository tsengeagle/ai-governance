請根據我提供的 `ai/project-context-bootstrap.yaml`，初始化此 repository 的 GitHub Copilot / agent mode 治理文件。

先根據 bootstrap 與 repo 結構判斷主要技術棧。不要預設所有 repo 都是 Grails。需至少能辨識：
- Grails legacy backend
- Flash / AIR / Flex legacy frontend
- Spring Boot backend
- Angular frontend
- Vue.js frontend

請固定產出以下共通文件：
1. `.github/copilot-instructions.md`
   - repository-wide 全域硬規則
   - 包含 backward compatibility、legacy grandfathering、no incidental refactor、validation、completion format

2. `AGENTS.md`
   - repo operating guide
   - 放 repository map、build/test、inspection order、representative files、docs index、escalation rules
   - 不要重複全域硬規則

3. `ai/project-context.yaml`
   - authoritative project context
   - 由 bootstrap 收斂而成
   - 若資訊不足，標示 assumptions / pending confirmation，不可虛構

再依技術棧產出 path-specific instructions：

- Grails:
  - grails-entrypoints.instructions.md
  - grails-service.instructions.md
  - grails-domain.instructions.md

- Spring Boot:
  - springboot-entrypoints.instructions.md
  - springboot-service.instructions.md
  - springboot-domain.instructions.md

- Flex / AIR / Flash:
  - flex-ui.instructions.md
  - flex-service-adapter.instructions.md

- Angular:
  - angular-components.instructions.md
  - angular-services.instructions.md

- Vue.js:

  - flask-config-appfactory.instructions.md

- 其他技術棧：根據 repo 結構與 bootstrap 判斷，產出相應的 path-specific instruction 文件  

所有 path-specific instructions 必須：
- 使用 applyTo
- 說明角色
- 列 allowed / forbidden behaviors
- 有 legacy grandfathering clause
- 有 when in doubt
- 不可為了遵守規則而強制重構既有程式碼

設計要求：
- 文件角色清楚，不可大量重複
- 全域規則、分層規則、repo context、project context 要分開
- 規則主要套用於新程式碼、實質修改邏輯、與新增邏輯
- 若理想架構與向下相容衝突，優先 backward compatibility
- AGENTS.md 必須 repo-specific
- 不要把 bootstrap 原文直接複製進所有文件；請做收斂、去重、分工
